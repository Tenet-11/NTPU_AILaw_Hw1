# LexiArbiter 法律文件標註工具

LexiArbiter 是以 PySide6 製作的法律文件標註工具，可在文件中標記專業術語、建立文件概念、設定上位概念，並為每一筆術語指定對應的解釋範圍。標註結果可以儲存成 `.lexa`，供之後繼續編輯與檢查。

## 1. 安裝與啟動

在 VS Code 開啟本專案資料夾後，於 PowerShell 終端機執行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

直接使用 `.venv` 裡的 Python 執行即可，不一定要先執行 `Activate.ps1`。若 VS Code 使用錯誤的 Python，請將直譯器切換為：

```text
.venv\Scripts\python.exe
```

## 2. 基本標註流程

1. 點選「開啟檔案」，載入 `.docx`、`.json` 或既有的 `.lexa`。
2. 將標註模式切換為「術語與解釋標註」。
3. 用滑鼠反白選取要標註的術語。
4. 點選「專業術語」。
5. 在概念視窗中選擇既有概念，或輸入新的文件概念。
6. 完成後，術語會以概念專屬的顏色顯示。

同一個文件概念在不同位置出現時，應選擇同一個既有概念，使這些標註共用相同的 `concept_id`。

## 3. 設定上位概念

必須先建立至少一筆術語及其文件概念，才能設定上位概念。

1. 點選工具列的「設定上位概念」。
2. 在步驟 1 從清單選擇「要被設定的既有概念」。
3. 在步驟 2 選擇既有的上位概念，或在下方輸入新的上位概念名稱。
4. 按下「確定」後，所有使用相同 `concept_id` 的術語都會更新為相同的 `broader_concept_id`。

若該概念已經是最上層概念，請在步驟 2 選擇它自己。例如「債之發生原因」是最上層概念時：

```text
文件概念：債之發生原因
上位概念：債之發生原因
```

上位概念不可留空，也不應建立「無」或「沒有」等假概念。

## 4. 標記解釋

每一筆術語都可以擁有自己的解釋範圍。

1. 先用滑鼠單擊要設定解釋的已標註術語。
2. 確認該術語成為目前選取的標註。
3. 用滑鼠反白選取完整的解釋文字。
4. 點選工具列的「標記解釋」。
5. 解釋範圍會以藍色顯示。

操作順序必須是：

```text
單擊術語 → 反白解釋 → 點選「標記解釋」
```

如果術語附近沒有另外提供解釋，解釋範圍應選取術語本身，不能留空。

相同概念的不同出現位置可以有不同的解釋，因此標記解釋時只會更新目前點選的那一筆術語，不會直接修改所有相同概念。

## 5. 相同術語與重疊範圍

標記專業術語後，程式可以搜尋文件中完全相同的文字並建立相同概念的標註。

- 相同概念會使用相同顏色。
- 不同概念會使用不同顏色，以方便辨識。
- 新標註若是較長的完整術語，例如「損害賠償請求權」，可以取代範圍內原本較短的「損害賠償」標註。
- 交叉重疊或其他不安全的重疊情況會略過，避免破壞既有資料。

使用老師提供的精確測試資料時，仍應按照標註任務單指定的文字範圍與順序操作，再將產出的 `.lexa` 與標準檔案比較。

## 6. 查看標註資訊

- 單擊已標註術語：狀態列會顯示術語、文件概念、上位概念與解釋。
- 將滑鼠停在術語上：Tooltip 會顯示該筆術語的完整關聯資訊。
- 將滑鼠停在藍色解釋上：Tooltip 會顯示它所對應的術語與概念。
- 點選右下角的文件概念：編輯器會跳到使用該概念的術語標註。

## 7. 儲存與輸出

點選「儲存進度」可將目前標註儲存成 `.lexa`。檔案中包含：

- 原始文件文字 `text`
- 文件概念池 `concepts`
- 術語範圍 `start`、`end`
- 術語標籤 `labels`
- 文件概念 `concept_id`
- 解釋範圍 `explanation_start`、`explanation_end`
- 上位概念 `broader_concept_id`

其中 `id` 與各概念 ID 是程式隨機產生的識別碼，不需要與老師範例使用完全相同的字串；重要的是 `concept_id` 與 `broader_concept_id` 所指向的概念名稱，以及各個文字範圍必須正確。

程式也會定期建立 autosave。正常完成標註後，仍應使用「儲存進度」建立正式的 `.lexa` 檔案。

## 8. 簡易測試資料

`簡易測試資料` 資料夾包含：

- `test_example.docx`：原始測試文件
- `readme.pdf`：11 筆標註的操作說明
- `test_example.lexa`：老師提供的正確結果

測試時應按照 `readme.pdf` 的順序及範圍完成 11 筆標註，再比較下列內容：

- `start`、`end`
- `explanation_start`、`explanation_end`
- `concept_id` 指向的概念名稱
- `broader_concept_id` 指向的上位概念名稱

概念 ID 的隨機字串不同屬於正常情況。
